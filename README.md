# Отчёт (ДЗ1)

## 0. О проекте

Проект посвящён разработке метода ускорения Qwen3-VL в задаче Video Question Answering. Целевой результат сформулирован количественно: ускорение инференса в 1,5–2 раза при ухудшении качества на бенчмарках менее чем на 0,5%. Агент используется как помощник исследователя: изучает литературу, реализует методы, пишет и запускает локальные тесты, подготавливает эксперименты и фиксирует результаты.

## 1. Среда в Git и цикл «порождение — проверка»

Основные правила в `AGENTS.md`, карта файлов — в `INDEX.md`. Для разных типов задач задан свой проверяемый результат:

- при изменении метода агент реализует код, добавляет локальный тест и запускает его без Kaggle и GPU;
- по явному запросу пользователя агент запускает готовый ноутбук в Kaggle, ждёт завершения, скачивает артефакты в новую папку внутри `results/` и добавляет описание запуска;
- при поиске литературы агент обращается к OpenAlex, записывает найденные работы в таблицу `library/<topic>.md` и записывает параметры поиска в `diary.md`.

Таким образом, цикл имеет вид:

```text
Запрос пользователя
        ↓
Определение типа задачи и критерия готовности
        ↓
Изучение INDEX.md, нужного кода, конфигураций и памяти
        ↓
Реализация или поиск литературы
        ↓
Локальная проверка / запуск Kaggle по отдельному запросу
        ↓
Фиксация результата, точки проверки и ограничений
```

Среда разделяет дешёвую проверку и ресурсозатратный эксперимент. Тесты выполняются локально на mock-данных, а Kaggle и GPU используются только по запросу. Это позволяет отбрасывать ошибки реализации до полного прогона модели.

## 2. Цикл агента своего проекта

Инструкции задают агенту не только цель, но и операционный протокол.

1. Агент определяет ожидаемый артефакт: изменение кода, обзор литературы либо результаты эксперимента.
2. По `INDEX.md` он находит нужную часть проекта: реализацию в `src/`, тесты в `src/tests/`, ноутбуки в `notebooks/` или источники в `library/`.
3. Для программной задачи агент вносит минимальное изменение и добавляет локальный тест. Проверка не должна требовать GPU или Kaggle.
4. Для экспериментальной задачи агент использует заданную конфигурацию, запускает ноутбук только после прямого запроса и сохраняет результаты без перезаписи существующих файлов.
5. После существенного изменения агент записывает в `diary.md` дату, запрос, сделанное изменение, результат, точку проверки и итог проверки. Краткая сводка для будущих сессий сохраняется также в `memory/`.

У цикла есть явные условия остановки. Эпизод ограничен десятью минутами; если время исчерпано, агент сообщает, что успел сделать и где остановился. После двух одинаковых сбоев проверки он прекращает повторные попытки и описывает причину. Решение пользователя требуется перед необратимым действием, при расхождении фактических данных с описанием и при неоднозначности, которая существенно меняет результат.

Границы безопасности также перечислены явно: нельзя читать или выводить секреты, удалять либо перезаписывать результаты, а `git push`, `rm -rf` и `sudo` нельзя выполнять без подтверждения. Агент действует самостоятельно в пределах локальных и обратимых изменений, но передает опасные или неоднозначные шаги человеку.

## 3. Сжатие статьи, AGENTS.md и файл-указатель

 В `AGENTS.md` - научная цель, критерии готовности, правила,ограничения, формат памяти. В `INDEX.md` - указатель. 
 В `library/` - краткое содержание статей.

## 4. Онтология и граф проекта

Ключевая сущность онтологии — `Experiment`, то есть один воспроизводимый запуск метода ускорения. Он связан ровно с одним `Method` (текстовое описание метода), одним `Measurement` (резуьтатом эксперимента), одним `Runner` (аргументы командной строки, с которыми выполнен запуск). У эксперимента также указаны тип GPU, хэш коммита, конфигурация с гиперпараметрами и отдельная директория результатов. `Method` содержит содержательное описание метода. `Measurement` хранит ссылку на `metrics.csv`.

```text
Experiment ──method──────────> Method
     │                            └── description
     ├──runner──────────> Runner
     │                            └── command-line arguments
     ├── experiment_id
     ├── hardware
     ├── config_file
     ├── commit_hash
     ├── results_directory
     └──measurement──────────> Measurement
                                  └── metrics_file
```

Схема записана в `ontology.yaml`, а классы описаны в `ontology/`. Каждый запуск получает отдельную папку `results/<experiment_id>/`, внутри которой находится `metrics.csv`. Такое представление связывает метод, версию кода, конфигурацию и измерения, и табличные данные в удобном формате. 

Пример графа представлен в `memory/experiment_graph.md`.

Для поиска литературы настроены инструменты OpenAlex: `openalex_search`, `openalex_work` и `openalex_links`. Любые данные из внешнего графа, попавшие в проект, сохраняются в `library/<topic>.md` в едином формате:

```text

```

- **Результат:** frame_sampling.md обновлён, все статьи с arXiv/CVPR имеют openalex_id и краткое описание.
- **Точка проверки:** `cat frame_sampling.md`

**Пример запроса:**  "Найди 5 статей, ускоряющ
их vlm в задаче обработки видео за счет прунинга внутри визуальной части (vit)." 

**Запись агента в `diary.md`:**

**Запрос:** Найти 5 статей, ускоряющих модели (VLM / VideoLLM для video QA).

5. **VETO** (2026) — dual-axis (spatial + temporal) token optimization, 45% faster inference

**Точка проверки:** `library/model_acceleration_vlm.md`
**Итог:** ✓ Статьи найдены и записаны. Все методы — training-free / plug-and-play, применимы к qwen3-vl.

# Что получилось и не получилось

Агент помогает с исправлением кода, тестированием и запуском в kaggle. Исправление кода и запуски неоднократно проверяла. Поиск по OpenAlex также отлично работает.

Но с созданием онтологии и логированием экспериментов в виде графа возникли проблемы - сначала агент неправильно понял структуру онтологии и все результаты запусков писал в markdown в один файл. Чтобы агент правильно сохранял все по отдельным yaml файлам в папке results, пришлось написать отдельный skill log-experiment. Тогда агент стал соблюдать правильную структуру онтологии и логов.
Я делаю вывод, что для соблюдения сложных правил, агенту требуется отдельная инструкция.
